# Model library and hotswapper

The native app has one Model Library entry from the sidebar and the composer’s model hotswapper. The library scans standard loopback endpoints for Ollama, GPT4All, LM Studio, Jan, LocalAI/llama.cpp, vLLM, KoboldCpp, and Text Generation WebUI, plus a configured custom loopback endpoint. Models with the same ID in different runtimes remain separate choices. Selecting or pinning a model preserves its provider and endpoint; pinning stays a small quick-switch subset while every discovered model remains in the library.

## Currently integrated sources

- **Installed models:** the app uses each responding local runtime's native inventory where available: Ollama `/api/tags`, LM Studio `/api/v1/models` (including model size and whether it is loaded), and OpenAI-compatible `/v1/models` for the remaining runtimes. The app does not request model catalogs from non-loopback addresses during this scan. A runtime that is stopped or has local API authentication enabled without app credentials cannot be inventoried.
- **Hugging Face Hub (GGUF):** the catalog has separate **Regular models** and **Uncensored / abliterated** searches. Both are filtered to GGUF and sorted by downloads. The uncensored lane searches the Hub for `uncensored`, `abliterated`, and `abliteration`, then includes only repositories whose ID or tags carry one of those explicit labels; regular search excludes those explicit labels. This is a catalog label, not a guarantee about model behavior. Installation is delegated to the LM Studio REST download API (`POST /api/v1/models/download` and its download-status route). Configure the chat endpoint to an LM Studio server, normally `http://localhost:1234/v1`, and keep that server running. Gated repositories require credentials configured in LM Studio; this app does not collect or forward Hub tokens for this route.
- **Ollama Library:** enter an Ollama model name such as `qwen3:8b`; installation uses the configured local Ollama server’s `POST /api/pull` streaming API. The current app does not offer remote registry search for Ollama names, so users need to know or paste the model identifier.
- **ModelScope Hub (GGUF):** search by name in the **Regular models** or **Uncensored / abliterated** lane. The app lists GGUF file packages only, groups split GGUF shards together, verifies each file's size, SHA-256, and GGUF signature, then creates the model in a local Ollama runtime through its blob and create APIs. The installed model is discovered in the normal inventory and can then be benchmarked and pinned. This path currently imports public GGUF repositories; it does not request or store a ModelScope token. An interrupted file download is cleaned up and restarts on the next attempt; resume support is not yet implemented.

The model quick switch is the dropdown directly above the typing box. It intentionally shows only the user's pinned provider/model/endpoint choices; the Model Library remains the complete inventory and pin management screen. When the current model is not pinned, the dropdown offers **Pin current model** so users can set up quick switching without leaving the composer. Pinned entries show the device's measured estimated tokens/second inline, with first-token time, sample count, and estimate method in the tooltip; models without measurements say **Not benchmarked**.

All discovered installed models remain in the Model Library regardless of pin state; pinning is only a shortcut for the handful of models used often. The dropdown directly above the composer shows pinned provider/model/endpoint profiles only; an active but unpinned model does not get added to the quick-switch list. If nothing is pinned, the menu explains that and offers **Pin current model** plus **Manage models…**. Pinned profiles are saved in the local settings file, including migration of older model-ID-only pins. Pinning is available for installed models, so an unfinished catalog download cannot appear in the hotswapper as a ready-to-use model. Selecting an LM Studio model loads it through the local REST API if it is downloaded but not loaded; other compatible runtimes select the model ID and refresh the connection.

For local endpoints, completed chat responses update per-model measurements saved on the device and scoped to the endpoint and model ID. The library shows sample count, average time to first token, and estimated tokens per second, with models having a measurement sorted first by observed throughput. **Benchmark selected** runs the same short, bounded prompt against one installed model on demand, so users can compare the models they actually use. It is local-only, pauses chat until finished or stopped, and incomplete runs are not recorded. Tokens per second is an estimate based on response characters because compatible local APIs do not consistently provide tokenizer counts. Unused models show "Not yet measured"; the app does not run tests in the background or invent performance scores.

## Compatibility boundaries

Model catalogs and model runtimes are different systems. A repository hosted on Hugging Face, ModelScope, Civitai, GitHub, or another site is not automatically usable for chat: it needs compatible weights, tokenizer/configuration, license/access, hardware, and a runtime import path. This implementation routes Hugging Face GGUF downloads through LM Studio, Ollama model names through Ollama pull, and ModelScope GGUF packages through a SHA-256-verified Ollama import. The official [ModelScope Hub SDK](https://github.com/modelscope/modelscope_hub) documents repository discovery and file downloads; its [ModelScope skills API guide](https://github.com/modelscope/modelscope-skills/blob/main/skills/ms-hub/SKILL.md) describes the public model search response and query parameters. The app uses ModelScope's file manifest and download API, verifies all GGUF shard hashes and signatures, and then uses Ollama's documented [blob upload](https://github.com/ollama/ollama/blob/main/docs/api.md#push-a-blob) and [GGUF create API](https://github.com/ollama/ollama/blob/main/docs/api.md#create-a-model-from-gguf). LM Studio documents downloads through its catalog or exact Hugging Face URLs in its [model download API](https://lmstudio.ai/docs/developer/rest/download), and external GGUF imports through its [model directory format](https://lmstudio.ai/docs/app/advanced/import-model). The app does not claim generic support for every host or arbitrary model architecture; add a new catalog only alongside a verified installer/import adapter, integrity/error handling, and an installed-model discovery path.

Official APIs used by this slice:

- [Hugging Face Hub model API](https://huggingface.co/docs/hub/api)
- [LM Studio model download API](https://lmstudio.ai/docs/developer/rest/download) and [download status API](https://lmstudio.ai/docs/developer/rest/download-status)
- [LM Studio models list API](https://lmstudio.ai/docs/developer/rest/list) and [model load API](https://lmstudio.ai/docs/developer/rest/load)
- [Ollama pull API](https://docs.ollama.com/api/pull)
- [Ollama local tags API](https://docs.ollama.com/api/tags)
- [Ollama create API](https://docs.ollama.com/api/create) (reviewed as an import route; requires the app to handle model blobs and SHA-256 mappings)
- [Ollama blob API](https://github.com/ollama/ollama/blob/main/docs/api.md#push-a-blob)
- [ModelScope Hub SDK](https://github.com/modelscope/modelscope_hub) and [official ModelScope API guide](https://github.com/modelscope/modelscope-skills/blob/main/skills/ms-hub/SKILL.md)

## ModelScope catalog and UI follow-up (2026-11-04)

ModelScope search and GGUF manifest routes were checked against the public service using `Qwen3-0.6B-GGUF`; the live search returned repository IDs and download counts, and the repository manifest returned GGUF paths, byte sizes, and SHA-256 values. A Windows app UI search surfaced embedding, ASR, projector, reranker, and guard-model repositories among regular chat models, and confirmed installed-model rows clear when switching sources. The reranker and guard repositories advertised text-generation tasks, so explicit non-chat name exclusions now take precedence over conflicting task metadata. The catalog also filters by task metadata (with conservative name-based exclusions when tasks are absent), removes MMProj/projector sidecars, cancels superseded catalog queries, and shows a searching state. Automated checks cover regular/uncensored filtering, conflicting reranker and guard task tags, chat-task exclusions, split-shard grouping, Ollama blob/create calls, digest mismatch, invalid GGUF signatures, and path traversal. `dotnet run --project native/ServerRock.Core.Tests/ServerRock.Core.Tests.csproj` passed after the latest filtering and identifier-validation changes. The `net10.0-desktop` target built with zero warnings. The Windows App SDK target built with the existing missing `win-AnyCPU.pubxml` (`NETSDK1198`) warning. The latest build's catalog result filtering and cancellation behavior still need a successful fresh UI runtime recheck. No real multi-gigabyte download/import was attempted; Ollama blob/create behavior is covered by stubbed HTTP tests.

## Native AI SuperMarket migration (2026-11-04)

The native Models action now opens **AI SuperMarket** directly instead of an empty, query-first library. Its default source is a populated Hugging Face GGUF catalog of chat-ready repositories; the user can refine it by model name or capability, switch between regular and explicitly labelled uncensored/abliterated results, download through the configured local LM Studio runtime, then switch to Installed models to select, pin, or benchmark the download. Ollama and ModelScope remain distinct sources so their installation behavior stays accurate. The action controls deliberately enable model selection, pinning, and benchmarking only for installed local models. `dotnet run --project native/ServerRock.Core.Tests/ServerRock.Core.Tests.csproj` and `dotnet build native/ServerRock.Native.sln --no-restore` passed after this migration slice. The new explicit `win-AnyCPU` profile maps the solution's default Windows configuration to the supported `win-x64` self-contained build, so the solution-level build is now warning-free.
